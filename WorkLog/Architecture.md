# GameServer 아키텍처 및 로직 분석 리포트 (2026-03-16)

본 리포트는 2026년 3월 16일 기준, 현재 구현된 GameServer의 핵심 시스템에 대한 심층 분석 결과를 담고 있습니다.

## 1. 비동기 처리 및 스레드 모델 (Concurrency)

### 1.1 JobQueue 시스템
- **동작 원리**: 모든 비즈니스 로직(필드, 플레이어, 세션)은 `JobQueue`를 상속받거나 `AsyncActor`를 통해 비동기적으로 실행됨.
- **Lock-Free 보장**: `_isExecute` 원자적 플래그와 CAS(Compare-And-Swap) 연산을 통해 단일 스레드 순차 실행을 보장함. 내부적으로 `moodycamel::ConcurrentQueue`를 사용하여 락 경합을 최소화함.
- **생명주기 관리**: `Job` 객체가 타겟의 `shared_ptr`을 보유하여, 비동기 실행 중 객체가 파괴되는 것을 방지함.

### 1.2 Worker 스레드 전략 (WorkerMain)
- **TLS 우선 순위**: 각 워커 스레드는 자신의 로컬 큐(`LJobQueue`)에 있는 작업을 먼저 처리하여 캐시 효율을 극대화함.
- **분산 처리**: 로컬 큐가 비면 `GGlobalJobQueue`에서 작업을 가져오며, 작업이 길어지면(10ms 초과) 다시 글로벌 큐에 반납하여 기아 현상(Starvation)을 방지함.
- **송신 최적화 (FlushSend)**: 패킷을 즉시 보내지 않고 루프 마지막에 모아서 전송하여 시스템 콜 오버헤드를 줄임.

## 2. 콘텐츠 로직 (Contents)

### 2.1 이동 및 경로 탐색 (Navigation)
- **Raycast 최적화**: `FindPath` 호출 시 먼저 `raycast`를 수행하여 장애물이 없는 직선 구간은 즉시 반환함. 이는 복잡한 경로 탐색 연산을 획기적으로 줄여줌.
- **서버 사이드 보간**: `PlayerCharacter::GetCurrentPosition`은 웨이포인트와 도달 시간(`_moveArrivalTimes`)을 기반으로 실시간 서버 위치를 계산함.
- **상태 동기화**: 필드 내 유저들에게 이동 경로(`SC_MOVE_PATH`)를 전송하며, 새로 입장한 유저에게는 현재 이동 중인 유저의 경로 데이터까지 동기화하여 화면 끊김을 방지함.

### 2.2 포탈 및 필드 전환
- **검증 로직**: 포탈 좌표 기준 500cm 이내인 경우만 이동을 허용하는 물리적 검증 수행.
- **자동 확장(Auto-scaling)**: `FieldManager`는 수용 인원이 꽉 찬 맵 입장 요청 시 자동으로 새 인스턴스를 생성하고, 플레이어가 0명이 되면 10초 후 자동 파괴함.
- **필드 이동 프로세스**: `GameManager::ProcessMoveField`를 통해 `Leave` -> `LoadingInfo 설정` -> `입장 패킷` 순으로 상태 전환을 완벽히 제어함.

## 3. 향후 고도화 과제 (Recommendations)
1. **포탈 쿨타임**: 패킷 스패밍 방지를 위한 시간 제한 필요.
2. **이동 속도 검증**: 서버 고정 속도와 클라이언트 전송 속도 간의 일치 여부 확인 로직 필요.
3. **DB 연동 준비**: 하드코딩된 입장 맵 ID(1000)를 플레이어 데이터 기반으로 전환.
